---
title: "Migrating Packages from v1alpha1 to v1beta1"
---

This guide migrates a `ZarfPackageConfig` definition from `zarf.dev/v1alpha1` to `zarf.dev/v1beta1`. Existing v1alpha1 definitions remain supported. A definition without `apiVersion` is treated as v1alpha1, whereas v1beta1 requires `apiVersion: zarf.dev/v1beta1`.

:::caution

The v1beta1 schema is experimental, and creating v1beta1 packages is behind a feature flag.

:::

## Replace removed features

Before converting, migrate these features while keeping the definition on v1alpha1. `zarf dev upgrade` errors if any of the following removed features are still in use:

| v1alpha1 field | Migration |
| --- | --- |
| `variables`, `constants`, `components[].charts[].variables`, Action `setVariables` | Follow [Variables to Values](/best-practices/variables-to-values/). Replace references in manifests, files, chart values files, and actions as well as declarations. |
| `components[].dataInjections` | Follow [Data Injections Migration](/best-practices/data-injections-migration/). |
| `metadata.yolo` | Remove it and deploy with `--connected`. See [Connected Mode](/ref/deploy/#additional-deployment-modes). |
| `components[].import.name` | See [Component imports](#component-imports). |
| `components[].group` | Use `only.flavor` in v1alpha1, converted to `selector.flavor` in v1beta1. This replaces deploy-time group selection with create-time filtering. |
| `components[].default` | Remove it. Default group members are not applicable and there is no way to set the default prompt answer. |
| `components[].only.cluster.distros` | Remove it. This field was unused and has no replacement. |

## Convert the definition

The command below performs all the automatic [field mappings](#schema-changes-and-field-mappings).

```bash
zarf dev upgrade zarf.yaml > zarf-v1beta1.yaml
```

YAML comments and formatting are not preserved. Imported definitions must be migrated separately.

## Component imports

Imports now reference `ZarfComponentConfig` files containing one component. A package or directory can no longer be imported directly, and skeleton packages are replaced by published component configs.

1. Convert the source package, then extract each imported component into its own file.
2. Move its name and description into `metadata`, and its resource and action fields under `component`. Keep `optional` and `selector` on the consuming package component.
3. Move flavor and architecture restrictions for the imported component into top-level `variant.flavor` and `variant.architecture`.
4. Copy required `values` declarations.
5. Replace `import.path` with `import.local[].path`, or `import.url` with `import.remote[].url`. Remove `import.name`.

```yaml
# components/app.yaml
apiVersion: zarf.dev/v1beta1
kind: ZarfComponentConfig
metadata:
  name: app
  version: 1.0.0
component:
  images:
    - name: ghcr.io/example/app:1.0.0
```

```yaml
# In the consuming package's components list
- name: app
  import:
    local:
      - path: components/app.yaml
```

When listing multiple imports, exactly one must match the create-time flavor and architecture. Empty variant fields match any target, so avoid overlapping variants.

For remote imports, set `metadata.version` and publish the component:

```bash
zarf component publish components/app.yaml oci://ghcr.io/example/components
```

Then replace the local import with:

```yaml
import:
  remote:
    - url: oci://ghcr.io/example/components/app:1.0.0
```

Remote components cannot contain `onCreate` actions or use `kustomize.allowAnyDirectory: true`. Move create actions into the consuming package. Render package templates before publishing, as described below.

## Package templates to `zarf dev template`

In v1beta1, package templates are rendered before `zarf package create` using a separate `zarf dev template` step.

1. Rename the migrated package definition from `zarf.yaml` to `zarf.tpl.yaml`.
2. Replace each `###ZARF_PKG_TMPL_KEY###` with `[[ .KEY ]]`. Keys are case-sensitive and accessed directly, without a `.Values` prefix.
3. Move template inputs from `zarf package create --set` to `zarf dev template --set KEY=value`, or supply a YAML mapping with `--set-file template-values.yaml`. `--set` overrides file values. Missing template values cause an error instead of an interactive prompt.

For example, a migrated `zarf.tpl.yaml`:

```yaml
apiVersion: zarf.dev/v1beta1
kind: ZarfPackageConfig
metadata:
  name: app
  version: "[[ .VERSION ]]"
components:
  - name: app
    images:
      - name: "[[ .IMAGE ]]"
```

Render it, then create the package:

```bash
zarf dev template --set VERSION=1.0.0 --set IMAGE=ghcr.io/example/app:1.0.0
zarf package create zarf.gen.yaml
```

Rendering writes `zarf.gen.yaml` alongside the template and validates the generated schema. Re-render whenever template inputs change.

For local component templates, render each `<name>.tpl.yaml` separately and set `import.local[].path` to `<name>.gen.yaml`. Remote components must be fully rendered before publishing and cannot be templated during import.

## Readiness checks

`healthChecks` becomes wait actions appended to `actions.onDeploy.onSuccess`:

```yaml
# After: component fields
actions:
  onDeploy:
    onSuccess:
      - wait:
          cluster:
            kind: Deployment.v1.apps
            name: app
            namespace: app
```

For a health check with `apiVersion: apps/v1` and `kind: Deployment`, the wait kind is `Deployment.v1.apps`. Core resources such as `Pod` keep their kind unchanged.

In v1beta1, omitting `wait.cluster.condition` waits for resource readiness using kstatus. Set `condition: exists` to wait only for existence. Conversion adds `exists` to old conditionless wait actions to preserve their behavior; converted health checks omit the condition to retain readiness checks.

## Schema Changes and Field Mappings

These conversions are automatic. Paths below are relative to each component unless prefixed with `metadata` or `build`. `[]` denotes a list entry.

| v1alpha1 | v1beta1 |
| --- | --- |
| `required` | `optional`, with the boolean inverted. |
| `only.flavor` | `selector.flavor` |
| `only.cluster.architecture` | `selector.architecture` |
| `only.localOS` | `target.os` |
| `charts[].noWait`, `manifests[].noWait` | `skipWait` on the same entry. |
| `manifests[].template`, `files[].template`, action `template` | `enableTemplating` on the same entry. |
| `files[].target` | `files[].destination` |
| `files[].shasum` | `files[].checksum`, prefixed with `sha256:`. Unprefixed checksums also mean SHA-256. |
| `manifests[].kustomizations` | `manifests[].kustomize.files` |
| `manifests[].kustomizeAllowAnyDirectory` | `manifests[].kustomize.allowAnyDirectory` |
| `manifests[].enableKustomizePlugins` | `manifests[].kustomize.enablePlugins` |
| Action/default `maxRetries`, `mute` | `retries`, `silent` |
| `actions.*.after` | Prepended to `actions.*.onSuccess`, before existing success actions. |
| `charts[].schemaValidation` | `charts[].skipSchemaValidation`, with the boolean inverted. |
| `charts[]` source fields and values files | See [Helm charts](#helm-charts). |
| `images[]` | See [Images](#images). |
| `repos[]` | `repositories[]`. See [Git repositories](#git-repositories). |
| `metadata.allowNamespaceOverride` | `metadata.preventNamespaceOverride`, with the boolean inverted. |
| `metadata.image`, `source`, `documentation`, `url`, `authors`, `vendor` | Same keys under `metadata.annotations`. Existing annotation values take precedence. |
| `metadata.aggregateChecksum` | `build.aggregateChecksum` |
| `build.terminal` | `build.hostname` |

New v1beta1 components are required by default (`optional: false`). However, conversion keeps current behavior (i.e., an omitted or false `required` becomes `optional: true`). Namespace overrides and chart schema validation remain enabled by default.

`selector` filters components during create; `target` filters them during deploy.

### Helm charts

Each chart must have exactly one source: `helmRepository`, `git`, `oci`, or `local`. Conversion moves the old source fields into that object:

| v1alpha1 chart source | v1beta1 chart source |
| --- | --- |
| Helm repository `url`, `repoName`, `version` | `helmRepository.url`, `helmRepository.name`, `helmRepository.version` |
| Git `url`, `gitPath`, `version` or URL `@ref` | `git.url`, `git.path`, `git.ref` |
| OCI `url`, `version` | `oci.url`, `oci.ref.tag`; digest references use `oci.ref.digest`. |
| `localPath` | `local.path`; remove `version` and use the chart's `Chart.yaml` version. |

Git charts require `ref` with exactly one of `tag`, `branch`, or `commit`. Conversion treats `refs/heads/<name>` as a branch, a full SHA as a commit, and other refs as tags. If the URL has no ref, the old chart `version` supplies it. Git URLs must no longer contain an `@ref` suffix.

OCI charts require exactly one of `ref.tag` or `ref.digest`. The URL must not contain a reference.

Chart values files become objects. Combine `valuesFiles` and `templatedValuesFiles` into `valuesFiles`:

```yaml
# Before: chart entry
name: app
namespace: app
url: oci://ghcr.io/example/charts/app
version: 1.0.0
valuesFiles:
  - chart-values.yaml
templatedValuesFiles:
  - runtime-values.yaml
```

```yaml
# After: chart entry
name: app
namespace: app
oci:
  url: oci://ghcr.io/example/charts/app
  ref:
    tag: 1.0.0
valuesFiles:
  - path: chart-values.yaml
  - path: runtime-values.yaml
    enableTemplating: true
```

Package-value mappings in `charts[].values` keep their `sourcePath` and `targetPath` fields.

### Images

`images` entries are objects:

```yaml
# Component fields
images:
  - name: ghcr.io/example/app:1.0.0
    source: registry
```

Images default to `source: registry`. For images stored in the Docker daemon, set `source: daemon`. v1beta1 does not fall back to the local daemon after a registry pull fails.

During component imports, images merge by `name` unless a matching non-empty `id` identifies the imported image. Set the same `id` on an imported image and its override to replace the image reference, such as when using an enterprise image in a custom init package:

```yaml
# Imported component
images:
  - id: registry
    name: registry:3

# Importing component
images:
  - id: registry
    name: enterprise.example.com/registry:3
```

Matching IDs take precedence over matching names. Non-empty fields on the importing image take precedence; omitted fields inherit the imported value. Images with neither a matching ID nor a matching name are appended.

### Git repositories

`repos` becomes `repositories`, with the Git ref separated from the URL:

```yaml
# Component fields
repositories:
  - url: https://github.com/example/app.git
    ref:
      branch: main
```

Omit `ref` to mirror all branches and tags.
