Users can use a config file to easily control flags for `zarf init`, `zarf package create`, and `zarf package deploy` commands, as well as global flags (excluding `--confirm`), enabling a more straightforward and declarative workflow.

Zarf supports config files written in `toml` and `yaml`. By default Zarf will look for a file called `zarf-config` with one of these filenames in the current working directory. To generate a blank config file you can run `zarf dev generate-config` with an optional output filename/format. For example, to create an empty config file with the `my-cool-env` in the yaml format, you can use `zarf dev generate-config my-cool-env.yaml`.

To use a custom config filename, set the `ZARF_CONFIG` environment variable to the config file's path. For example, to use the `my-cool-env.yaml` config file in the current working directory, you can set the `ZARF_CONFIG` environment variable to `my-cool-env.yaml`. The `ZARF_CONFIG` environment variable can be set either in the shell or in a `.env` file in the current working directory. Note that the `ZARF_CONFIG` environment variable takes precedence over the default config file path.

Additionally, you can set any supported config parameter via an environment variable using the `ZARF_` prefix. Note that the `ZARF_` environment variable takes precedence over a config file.

### Environment Variable Name Mapping

Zarf binds environment variables using Viper with a `ZARF_` prefix and converts key delimiters (such as `.` in nested config paths) to underscores (`_`), matching in uppercase:

- **Single-level keys**: `architecture` -> `ZARF_ARCHITECTURE`, `log_level` -> `ZARF_LOG_LEVEL`, `tmp_dir` -> `ZARF_TMP_DIR`.
- **Nested keys**: `package.deploy.timeout` -> `ZARF_PACKAGE_DEPLOY_TIMEOUT`, `init.git.url` -> `ZARF_INIT_GIT_URL`.
- **Hyphenated flags & parameters**: Command-line flags and parameters (such as `--oci-concurrency` or `package.oci_concurrency`) map to underscore-separated uppercase environment variables (e.g., `ZARF_PACKAGE_OCI_CONCURRENCY`).

### Configuration Precedence

Configuration sources are evaluated in the following order of precedence (highest to lowest):

1. **Command line flags** (e.g., `--log-level debug`)
2. **Environment variables** (e.g., `ZARF_LOG_LEVEL=debug`)
3. **Custom config file** (specified via `ZARF_CONFIG` path or `.env`)
4. **Default config file** (`./zarf-config.yaml` or `~/.zarf/zarf-config.yaml`)
5. **Built-in default values** (e.g., log level default `info`)

For example, if a config file sets `log_level: info`, the environment variable `ZARF_LOG_LEVEL=warn` will override it, and passing `--log-level debug` on the CLI will take highest precedence and set the log level to `debug`.

## Config File Location

Zarf searches for the Zarf Config File from either your current working directory or the `~/.zarf/` directory if you don't specify a config file.
